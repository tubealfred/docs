TubeAlfred gives applications, agents, and command-line workflows a consistent way to work with public YouTube data.

Choose the interface that fits your workflow:

- **REST API** for applications, scripts, workers, and internal services. Start with the [quickstart](/quickstart), then use the generated API reference in this site.
- **Hosted MCP** for Claude and other MCP-compatible clients. Follow the [MCP guide](/guides/mcp).
- **CLI** for terminal use and shell automation. Follow the [CLI guide](/guides/cli).

## Authentication

<span id="docs-code-auth-bearer" /><span id="docs-code-auth-x-api-key" />

REST and developer MCP clients can use a team API key. Claude web and mobile use OAuth when connecting to the hosted MCP server. See [Authentication](/guides/authentication) for the supported flows.

## Response envelope

<span id="docs-code-envelope-success" /><span id="docs-code-envelope-failure" />

Successful REST responses use a `status: "success"` envelope with the endpoint-specific payload in `data`. Failures use the HTTP status code and a flat object that always includes `message`. See [API concepts](/guides/api-concepts#response-envelope).

<span className="block scroll-mt-32" id="data-freshness" />

## Data freshness and reliability

Data is fetched on demand and may pass through short-lived caches. TubeAlfred does not promise a universal freshness window, real-time results, historical completeness, or a public freshness SLA. Read [public-data boundaries](/guides/api-concepts#public-data-boundaries) and [data sources and reliability](https://tubealfred.com/data-sources).

## Pagination

<span id="docs-code-pagination-first" /><span id="docs-code-pagination-first-response" /><span id="docs-code-pagination-next" />

List operations return `data.continuation_token` when another page is available. Treat tokens as opaque, keep them with the original query, and fetch another page only when needed. See [Pagination](/guides/api-concepts#pagination).

<span className="block scroll-mt-32" id="idempotency" />

## Idempotency and retries

POST pagination and batch operations accept `Idempotency-Key`. Matching retries of the identical validated request within 24 hours replay the first successful response; conflicting reuse returns HTTP 409. See [Retries and idempotency](/guides/api-concepts#retries-and-idempotency).

## Versioning

Public operations use `/v1/youtube/*`. Clients should tolerate additive response fields and optional parameters. Breaking changes use a new versioned path. See [Versioning](/guides/api-concepts#versioning).

## Errors

Branch on HTTP status and documented error code instead of matching message text. Common HTTP statuses:

- <span id="error-400" /><span id="docs-code-error-400" />`400` invalid request or pagination state
- <span id="error-401" /><span id="docs-code-error-401" />`401` invalid or missing credentials
- <span id="error-402" /><span id="docs-code-error-402" />`402` insufficient team credits
- <span id="error-403" /><span id="docs-code-error-403" />`403` scope, team, or content restriction
- <span id="error-404" /><span id="docs-code-error-404" />`404` unavailable resource
- <span id="error-409" /><span id="docs-code-error-409" />`409` idempotency conflict or in-progress request
- <span id="error-422" /><span id="docs-code-error-422" />`422` invalid endpoint parameter
- <span id="error-429" /><span id="docs-code-error-429" />`429` TubeAlfred or upstream rate limit
- <span id="error-500" /><span id="docs-code-error-500" />`500` response processing failure
- <span id="error-502" /><span id="docs-code-error-502" />`502` upstream request failure
- <span id="error-503" /><span id="docs-code-error-503" />`503` temporary upstream unavailability
- <span id="error-504" /><span id="docs-code-error-504" />`504` upstream timeout

See [Errors](/guides/api-concepts#errors) and the generated endpoint reference for response schemas.

## Data handling

TubeAlfred records usage and lightweight request insights for billing, quota, and product quality. It does not store raw comments, raw transcripts, full descriptions, upstream response bodies, request headers, or plaintext API keys by default.

## What TubeAlfred provides

TubeAlfred exposes read-only operations for public YouTube data, including videos, channels, playlists, comments, transcripts, captions, and search. The exact operation catalog and schemas come from the production [OpenAPI specification](https://tubealfred.com/openapi.json).

TubeAlfred is an independent service. It is not the official YouTube Data API, and it does not provide private YouTube Studio analytics or write access to YouTube accounts.
